# Metria 0.1.0

Metria's first Alpha release verifies a local llama.cpp CPU thread-count change
and saves the evidence behind the comparison.

Use it to check whether the requested threads actually ran and whether the
sampled token trajectories changed, while keeping the pinned GGUF, capture
provider, prompts, and other settings fixed. Missing or conflicting runtime
evidence prevents a verified result.

After PyPI publication, install with Python 3.10–3.14:

```bash
python -m pip install metria==0.1.0
metria --version
metria verify study.json --output verification
```

The wheel has no runtime dependencies. The native llama.cpp provider and model
are prepared separately. The source archive includes the pinned build helper,
capture patch, upstream license, and recipe preparation tool.
Follow the [complete local setup guide](https://github.com/dipeshbabu/metria/blob/metria-v0.1.0/docs/guides/metria-verify.md)
before running the verification command.

Each verification retains `manifest.json`, `report.md`, and both run records.
The CLI also supports recipe validation/digesting/normalization, model capability
inspection, and saved-record comparison. Python APIs expose study execution,
runtime adapters, identity, and measurement evidence.

The end-to-end workflow is qualified on Linux/Ubuntu WSL with local CPU inference.
Core and package-install checks also run on Windows and macOS.
`VERIFIED` means comparison evidence and analysis are complete; it does not
certify model quality, a speedup, or deployment acceptance. GPU settings,
quantization, runtime upgrades, chat templates, and repeated-trial policies are
outside this first CLI scope. Public APIs remain provisional.

Review run records before sharing: requested configuration can contain prompt
text and local paths. Summary reports omit raw prompts and generated text.

The attached wheel and source archive have accompanying SHA-256 checksums.
See the [changelog](https://github.com/dipeshbabu/metria/blob/metria-v0.1.0/CHANGELOG.md)
for the complete release scope.
